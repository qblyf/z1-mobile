## 一、功能概述

### 1.1 定位

零售开单是 Z1 门店管理系统的**核心销售入口**，面向一线职员/店长，支持在门店现场完成商品选购、优惠计算、收款、打印小票的完整闭环。

### 1.2 业务场景

- **门店零售**：顾客到店购物，职员扫码/搜索商品、收款、打印小票
- **会员消费**：绑定会员卡号，自动应用会员价、积分、优惠券
- **散客销售**：无需绑定会员，直接开单
- **批发/工程**：不同销售类型对应不同价格体系、发票类型

### 1.3 核心价值

- **快速开单**：扫码 3 秒内找到商品，全程 < 2 分钟完成一笔交易
- **精准优惠**：会员价、优惠券、积分、代金券、满赠自动叠加计算
- **灵活收款**：支持现金、微信、支付宝、银行卡、组合支付
- **离线可用**：断网时本地缓存，网络恢复后自动同步

## 五、页面详细说明

### 5.1 零售开单入口 `/order/retail/entry`

**功能描述**：零售开单的第一步，选择销售类型，并根据需要绑定会员。

**销售类型**：
- **零售**（默认）：标准零售价格体系
- **批发**：批发价格体系，可能有最低起订量
- **工程**：工程项目价格，通常有账期

**会员绑定方式**：
1. **扫码绑定**：扫描会员二维码/企业微信客户二维码
2. **手机号绑定**：输入手机号搜索会员
3. **散客开单**：不绑定会员，直接进入购物车

**交互逻辑**：
- 进入页面后自动检测是否为企微环境，是则显示扫码入口
- 选择销售类型后不可更改（影响价格体系）
- 会员绑定后可解绑重新选择
- 散客模式下不可使用会员价、积分、优惠券

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| salesType | enum | 销售类型：retail / wholesale / engineering |
| memberIdent | string | 会员 ident（绑定后） |
| fromSource | enum | 来源：scan / phone / walk-in |

**边界情况**：
- 手机号未注册 → 提示"该手机号未注册"，可引导新建会员
- 会员已绑定 → 提示"当前已绑定会员 XXX，解绑请返回重新选择"
- 企微扫码失败 → 提示"扫码失败，请检查网络后重试"或切换手机号绑定

### 5.2 会员信息页 `/order/retail/member`

**功能描述**：零售场景下展示已绑定会员的核心信息，作为购物车页面的顶部信息区。

**页面元素**：

| 元素 | 说明 |
|------|------|
| 会员头像 | 默认头像（根据性别） |
| 会员姓名 + 手机号 | 基础信息 |
| 会员等级标签 | 渐变色标签（普通/银卡/金卡/钻卡等） |
| 可用积分 | 醒目展示，精确到分 |
| 会员标签 | 如"老客户""高价值"等 |
| 今日消费 | 今日在当前门店的消费累计 |
| 快捷操作按钮 | 积分查询 / 积分调整 / 查看优惠券 / 查看历史 |

**积分规则**：
- 积分 = 消费金额（元）× 积分倍率（会员等级决定）
- 积分可抵扣现金（1积分 = 1分钱）
- 积分有效期：获得后 N 年内有效（可配置）

**交互逻辑**：
- 会员信息从 `/member/detail` 接口获取
- 积分实时更新（每次订单完成后刷新）
- 点击"积分调整"需权限（店长/管理员）
- 点击"查看优惠券"弹出优惠券列表
- 点击"查看历史"进入会员详情消费记录

**状态定义**：

| 状态 | 说明 |
|------|------|
| loading | 加载中，显示骨架屏 |
| loaded | 正常展示会员信息 |
| member | 已绑定会员 |
| walk-in | 散客模式，显示"散客"标签，无积分 |

### 5.3 商品选购页 `/order/retail/edit`

**功能描述**：零售开单的**核心页面**，包含商品分类浏览、搜索、扫码、商品详情、购物车管理。

**页面布局**：

```
┌─────────────────────────────────────────┐
│  ← 返回   零售开单         🔍  📷       │ ← 顶部导航（glassmorphism）
├─────────────────────────────────────────┤
│  [销售类型标签]  [会员信息卡片 ▼]        │ ← 顶部信息（可折叠）
├───────────┬─────────────────────────────┤
│ 分类侧栏   │                             │
│           │  商品网格                     │
│  全部      │  ┌────┐ ┌────┐            │
│  黄金      │  │商品│ │商品│            │
│  钻石      │  │卡片│ │卡片│            │
│  银饰      │  └────┘ └────┘            │
│  ...       │                             │
│           │                             │
├───────────┴─────────────────────────────┤
│ 🛒 12件 │ 合计 ¥3,256.00 │ [去结算]    │ ← 底部购物车浮动栏
└─────────────────────────────────────────┘
```

**顶部信息栏**：
- 销售类型标签（零售/批发/工程，不可修改）
- 会员信息卡片（可折叠，展开显示：姓名/积分/今日消费）
- 散客模式：显示"散客"标签，无积分显示

**搜索栏 + 扫码按钮**：
- 搜索框：支持商品名称、条码、品牌名模糊搜索
- 扫码按钮：调起相机扫描商品条码/EAN 码
- 扫码结果：直接弹出商品详情弹窗

**商品分类侧栏**：
- 固定宽度（80px），可滚动
- 当前选中分类高亮（蓝色背景）
- 显示分类名称 + 商品数量

**商品网格**：
- 每行 2 个商品卡片
- 每个卡片内容：商品图片、名称、库存标签、价格区
- 价格区：原价 / 会员价（折后价）
- 库存标签：绿色"有货" / 橙色"仅剩N件" / 红色"缺货"
- 加购按钮：点击即加1件，显示成功提示

**底部购物车浮动栏**：
- 购物车图标 + 商品总件数
- 合计金额（包含优惠前的总价）
- "去结算"按钮（主色调，醒目）

**购物车弹出层**（点击底部购物车）：
- 商品列表：图片 + 名称 + 单价 + 数量修改 + 删除
- 数量修改：`-` 和 `+` 按钮，步进器
- 备注输入：每个商品可单独备注
- 合计金额（折后）
- 优惠信息（已应用的优惠）
- 删除全部按钮
- "确认"按钮 → 关闭弹窗进入订单确认页

**商品详情弹窗**：

| 区块 | 内容 |
|------|------|
| 图片轮播 | 商品多图，支持左右滑动 |
| 基本信息 | 商品名称、SKU、条码、库存 |
| 价格区 | 原价 / 会员价 / 活动价，三选一展示 |
| 服务项选择 | 如有服务项，显示可选服务列表（可多选） |
| 数量步进器 | 最小1，最大99 |
| 按钮区 | [加入购物车] / [立即购买] |

**边界情况**：
- 商品库存为 0 → 显示"缺货"标签，加购按钮禁用
- 扫码商品不存在 → Toast 提示"未找到该商品，请检查条码"
- 网络断线 → 本地缓存商品列表，购物车数据本地存储
- 购物车为空 → 点击"去结算"无反应，显示空状态提示

**订单摘要区**：
- 商品缩略图列表 + 总件数
- 点击"查看"展开完整商品清单（可收起）
- 每个商品：图片 + 名称 + 数量 + 小计

**优惠应用区**：

| 优惠类型 | 操作 | 说明 |
|----------|------|------|
| 优惠券 | [选择] 按钮 | 弹出可用优惠券列表 |
| 积分抵扣 | [使用] 按钮 | 弹出积分使用界面（全额/部分/不使用） |
| 代金券 | 自动应用 | 可选择不使用已自动匹配的代金券 |
| 满赠 | 自动展示 | 满足满赠条件时自动显示赠品 |

**积分抵扣规则**：
- 输入使用积分数（1积分 = 1分钱）
- 最大可使用积分 ≤ 订单应付金额
- 也可选择"使用全部可用积分"
- 积分输入框下方显示："当前可用积分 XXXX，可抵 ¥XX.XX"

**优惠券选择弹窗**：
- Tab：可用优惠券 / 不可用优惠券
- 不可用原因：未满足条件 / 已过期 / 该商品不可用
- 每个优惠券卡片：面额、条件（满减门槛）、有效期
- 选中后自动计算优惠金额

**备注输入**：
- 单行文本输入，最大 200 字符
- Placeholder："选填，可添加订单备注"

**应付金额计算**：

```
商品小计总和
- 优惠券优惠
- 积分抵扣
- 代金券抵扣
= 应付金额
```

**提交订单按钮**：
- 点击后调 `emplAddMallOrder` 接口
- loading 状态：按钮显示加载中，禁止重复点击
- 成功 → 跳转支付页
- 失败 → Toast 提示错误原因，按钮恢复可点击

```
│  │          [确认收款]                  │ │

```

**支付方式列表**：
- 单选列表（现金/微信/支付宝/银行卡/组合支付）
- 支持多选（组合支付模式）
- 每种支付方式显示名称 + 图标

**组合支付**：
- 选择"组合支付"后，展开金额输入区
- 每种支付方式下方显示已输入金额
- 总金额 = 各支付方式之和，超出或不足均有提示
- 实付金额 = 实际收款金额
- 找零 = 实付 - 应付（现金场景下计算找零）

**收款操作流程**：
1. 选择支付方式
2. （扫码支付）展示收款二维码，等待支付完成回调
3. （现金）输入实收金额，自动计算找零
4. 点击"确认收款"
5. 调 `mallOrderPaid` 接口标记已付款
6. 跳转订单详情页

**边界情况**：
- 二维码过期（超时）→ 提示"二维码已过期"，重新生成
- 网络断线 → 缓存订单状态，恢复后自动重试
- 顾客取消支付 → 返回订单确认页，可重新选择支付方式

## 八、优惠计算规则

### 8.1 优先级与叠加逻辑

```
商品标价
    │
    ▼
1. 会员价（自动应用，根据会员等级查表）
    │
    ▼
2. 活动价（直降/秒杀，优先于会员价，两者取低）
    │
    ▼
3. 优惠券（满减/折扣，满足条件后应用）
    │
    ▼
4. 积分抵扣（从应付金额中抵扣，1积分=1分钱）
    │
    ▼
5. 代金券（从应付金额中抵扣，面额固定）
    │
    ▼
6. 满赠（满足金额门槛自动赠品，不可与优惠券同享时取最优）
```

### 8.2 优惠叠加规则表

| 优惠A | 优惠B | 叠加规则 |
|-------|-------|----------|
| 会员价 | 直降活动 | 取最优（价格更低） |
| 会员价 | 优惠券 | 可叠加 |
| 直降活动 | 优惠券 | 优惠券标注不可与活动同享时，取最优 |
| 积分抵扣 | 优惠券 | 可叠加 |
| 积分抵扣 | 代金券 | 可叠加 |
| 满赠 | 优惠券 | 视活动配置，部分满赠不可与优惠券同享 |
| 以旧换新 | 其他优惠 | 可叠加 |

### 8.3 积分规则

- 积分获取：消费 1 元 = N 积分（会员等级决定 N 值）
- 积分抵扣：1 积分 = 1 分钱
- 积分有效期：获得后 2 年内有效（可配置）
- 积分不足时：不可使用超过实际积分的数量

## 十、离线需求

### 10.1 离线操作场景

| 场景 | 离线行为 | 恢复同步 |
|------|----------|----------|
| 断网开单 | 本地缓存购物车，订单暂存本地 | 网络恢复后自动提交，订单状态为"pending_sync" |
| 断网收款 | 本地记录收款信息 | 网络恢复后调用 paid 接口 |
| 断网商品搜索 | 显示本地缓存商品 | 仅支持缓存商品范围内搜索 |

### 10.2 离线数据缓存策略

| 数据类型 | 缓存方式 | 同步策略 |
|----------|----------|----------|
| 商品列表 | SQLite 本地库，按分类下载 | 每日增量同步 |
| 会员信息 | 缓存最近访问的会员 | 实时同步已访问会员 |
| 购物车 | 内存 + 本地持久化 | 提交后清空 |
| 订单 | 本地暂存（未提交） | 网络恢复后按顺序提交 |

### 10.3 冲突处理

- 同商品库存变化：提示用户商品库存已变化，确认是否继续
- 价格变化：提示用户商品价格已更新，重新计算
- 积分变化：实时拉取最新积分，以服务器为准

## 十三、App 设计差异（对比 PWA）

| 方面 | PWA 实现 | Flutter App 优化 |
|------|----------|------------------|

| 会员绑定 | 企微扫码（独享） | 企微扫码 + 相机扫码 + 手机号三通道 |
