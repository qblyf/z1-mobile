### 3.3 核心交互逻辑

#### 状态操作

| 状态 | 可操作 |
|------|--------|
| `unpaid`（待支付） | 支付定金 |
| `paid`（已支付） | 转为正式订单、申请退款 |
| `completed`（已完成） | 查看订单 |
| `apply-refund`（申请退款） | 审核退款 |
| `refunded`（已退款） | — |
| `canceled`（已取消） | — |

#### 转为正式订单

> ⚠️ 重要：预订单转正式订单需要先调用 `/mall-order/add` 创建商城订单，再调用 `/pre-sale-order/edit` 设置 `mallOrderNumber`

1. 点击"转为正式订单"
2. 调用 `/mall-order/add` 创建商城订单
3. 调用 `/pre-sale-order/edit` 设置 `mallOrderNumber` 和 `toOrderAt`
4. 更新预订单状态为 `completed`
5. 成功后跳转到商城订单详情

**接口调用顺序**：
```
POST /mall-order/add          → 创建商城订单，返回 mallOrderNumber
POST /pre-sale-order/edit     → { id, mallOrderNumber, toOrderAt }
```

#### 申请退款

1. 点击"申请退款"
2. 填写退款原因
3. 调用 `/pre-sale-order/return-refund` 申请退款
4. 预订单状态变为 `apply-refund`
5. 审核通过后退还定金，状态变为 `refunded`

## 六、状态流转

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  [待支付] ──→ [已支付] ──→ [已完成]                   │
│     ↓              ↓                                    │
│  [已取消]    [申请退款] ──→ [已退款]                   │
│                      ↓                                  │
│                 [已拒绝]                               │
│                                                         │
└─────────────────────────────────────────────────────────┘

流程说明：
1. 创建预订单 → 待支付
2. 支付定金 → 已支付
3. 支付尾款 → 已完成（转正式订单）
4. 申请退款 → 待审核 → 已退款 / 已拒绝
5. 取消订单 → 已取消
```

## 七、金额计算

> **⚠️ 注意**：`PreSaleOrderPayment` 只包含 `platform` 和 `content`，定金支付金额需从其他接口获取

| 字段 | 说明 |
|------|------|
| `amount` | 预订总价（分） |
| `expandAmount` | 膨胀金额（分），定金可抵扣更多 |
| 已付定金 | 需调用支付记录接口获取 |
| 待付尾款 | `amount - expandAmount - 已付定金` |

## 八、异常/边界情况

| 场景 | 处理 |
|------|------|
| 列表为空 | 显示空状态"暂无预订单" |
| 订单已过期 | 显示过期提示，隐藏支付按钮 |
| 支付失败 | 显示错误提示，可重试 |
| 网络错误 | 显示错误提示，可重试 |
| 退款审核拒绝 | 显示拒绝原因 |
