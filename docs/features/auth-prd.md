| 路径 | 名称 | 触发 |
|------|------|------|
| `/login` | 登录页 | 未登录访问任意页面 / token 失效 |

## 一、登录

### 1.1 入口

```
App 启动
   ↓
本地是否有有效 token？
   ├─有 → 进入首页（/home）
   └─无 → 跳转登录页（/login）
```

### 1.2 登录页布局

```
┌──────────────────────────────────┐
│                                  │
│           Z1 全网连锁              │
│                                  │
│  [手机号        ]                │
│  [验证码  ] [获取]               │
│                                  │
│  [   登录    ]                   │
│                                  │
└──────────────────────────────────┘
```

### 1.3 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/members/phone-login` | POST | 手机号 + 验证码登录 |

请求参数：参考后端 `z1-mid` 类型定义。

**返回**：成功返回 token + refreshToken + 用户基本信息。

### 1.4 登录后流程

1. 保存 token / refreshToken 到本地（`flutter_secure_storage`）
2. 调用 `/members/self` 拉取完整用户信息
3. 跳转首页 `/home`

## 二、Token 刷新

### 2.1 时机

| 场景 | 处理 |
|------|------|
| 请求返回 401 | 拦截器自动调用 `/auth/refresh-token`，成功后重放原请求 |
| App 启动检测 token 过期 | 主动刷新一次 |
| RefreshToken 也过期 | 清空本地凭证 → 跳转登录页 |

### 2.2 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/auth/refresh-token` | POST | 用 refreshToken 换新的 token |

## 三、登出

### 3.1 入口

profile 页底部"退出登录"按钮。

### 3.2 流程

```
点击"退出登录"
   ↓
确认对话框（防误触）
   ↓
调用 /auth/logout
   ↓
清空本地 token / 用户信息 / 缓存
   ↓
跳转登录页 /login
```

### 3.3 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/auth/logout` | POST | 服务端清除 session |

## 四、核心交互逻辑

### 4.1 验证码倒计时

- 点击"获取验证码"按钮 → 发送验证码 → 按钮置灰 + 显示 60s 倒计时
- 倒计时期间不可重复点击；倒计时结束按钮恢复"重新获取"
- 离开页面时清除定时器，避免内存泄漏

### 4.2 401 拦截器

- 全局 Dio 拦截器捕获 401 响应
- 触发 `/auth/refresh-token`：成功 → 用新 token 重放原请求；失败 → 清空凭证跳登录
- 并发请求场景：用 mutex 锁保证同一时间只发起一次 refresh，其他请求挂起等待

### 4.3 自动登录

- App 启动时读取本地 token，若存在且未过期，跳过登录页直接进首页
- token 过期但 refreshToken 有效：先静默刷新再进首页
- 双重失效：清空本地凭证，跳登录页

### 4.4 防误触登出

- 登出按钮触发前弹 `CupertinoAlertDialog` 二次确认
- 确认后清空：token / refreshToken / 用户信息 / 业务缓存（购物车、草稿等）

## 六、状态流转

```
[未登录] ──login──→ [已登录]
   ↑                    │
   │                  401 / refresh 失败
   │                    │
   └────logout──── [登录态]
                        │
                  /auth/refresh-token
                        ↓
                   [token 已刷新]
```

| 状态 | 含义 | 凭证 |
|------|------|------|
| 未登录 | 本地无 token | — |
| 已登录 | 本地有 token，未过期 | token 在请求头 Authorization |
| Token 过期 | 401 拦截器触发刷新 | 用 refreshToken 换新 token |
| 登录失效 | RefreshToken 也过期 | 清空本地凭证，跳登录页 |

---

## 七、异常/边界

| 场景 | 处理 |
|------|------|
| 验证码错误 | Toast "验证码错误" |
| 验证码过期 | Toast "验证码已过期，请重新获取" |
| 手机号未注册 | Toast "该手机号未注册" |
| 网络异常 | Toast "网络异常，请重试"，按钮恢复可点击 |
| Token 刷新失败 | 清空本地凭证 → 强制跳登录页 |
| 双重登录 | 后端返回特定错误码 → 提示"账号在其他设备登录" |

## 八、模块关联

```
启动 App
   │
   ↓
检查本地 token
   ├─无效 → /login
   │           │
   │           ↓
   │      手机号 + 验证码
   │           │
   │           ↓
   │      /members/phone-login → 获取 token
   │           │
   │           ↓
   │      /members/self → 拉取用户信息
   │           │
   │           ↓
   └─有效 ─→ /home（首页）
              │
              ↓
        所有需要 auth 的请求
              │
        ┌─────┴─────┐
        │           │
       200          401
        │           │
        │           ↓
        │      /auth/refresh-token
        │           │
        │       ┌───┴───┐
        │       │       │
        │      成功    失败
        │       │       │
        │       ↓       ↓
        └───── 重放原请求  /login（强制）
```

| 来源 | 触发 | 目标 |
|------|------|------|
| App 启动 | token 无效 | `/login` |
| 任意请求 | 401 | refresh-token 拦截器 |
| profile 页 | "退出登录" | `/auth/logout` → `/login` |
