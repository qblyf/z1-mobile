## 一、页面路径总览

```
换货
├── /order/list              → 订单列表（筛选 types=3）
│         ↓
│   /order/:orderNumber     → 订单详情（显示换货商品）
│         ↓
│   /order/change/add       → 新建换货（调用门店换货/网销换货/批发换货）
```

**⚠️ 重要说明**：
- 换货是销售订单的一种类型，通过 `type = 3`（SalesType.change）标记
- 换货订单通过 `/order/shop-sale-list?types=3` 筛选
> ⚠️ 注意：后端 Order 类型使用 `type` 字段表示销售类型，不是 `salesType`
- 后端只有创建换货接口 `/order-change/add/shop-sale`（门店换货）、`/order-change/add/net-sale`（网销换货）、`/order-change/add/out-sale`（批发换货）
- **⚠️ 暂未发现换货列表/详情接口**，需向产品确认是否需要开发

### 3.3 核心交互逻辑

2. 添加换入商品 → 选择新商品
3. 系统自动计算差价
4. 提交换货 → 调用换货接口

## 六、状态流转

换货订单复用销售订单的 `OrderStatus` 状态机（`types=3` 标识换货）：

| 值 | key | 中文 |
|----|-----|------|
| 1 | shippedPaid | 已发货已付款 |
| 2 | shippedUnpaid | 已发货未付款 |
| 3 | unshippedUnpaid | 未发货未付款 |
| 4 | unshippedPaid | 未发货已付款 |
| 5 | cancelled | 已取消 |

> 源码：`order-types.dart:54`。换货特殊点：原订单一般已是 `shippedPaid`，换货单创建后走自己的状态流。

### 6.1 换货特定流程

```
[原订单 已售]
     │
     │ 顾客带商品到店申请换货
     │
     ↓
[新建换货单 unshippedUnpaid 或 unshippedPaid（按补差价/退差价决定）]
     │
     │ 库存调整：原商品入库 + 新商品出库
     │ 财务对账：补差价 / 退差价
     │
     ↓
[换货完成 shippedPaid]
```

> ⚠️ 换货的"补差价支付方式"在源码中未见明确定义，需后端确认。

## 七、异常/边界情况

| 场景 | 处理建议 |
|------|---------|
| 原订单已退款 | 不允许换货，提示"订单已退款，无法换货" |
| 原订单已发起退货申请 | 不允许换货，引导用户先处理退货 |
| 原订单已超过换货期 | 提示"已超过换货期限，无法换货"，期限由后端配置 |
| 换入商品库存不足 | 列表显示缺货标签，禁选 |
| 换出商品序列号已不在库 | 提示"该商品序列号已变更，无法找回" |
| 补差价为负（退差价）| 引导走退款流程或现金退还 |
| 补差价为 0 | 跳过支付步骤，直接完成 |
| 网络错误 | 创建接口失败时保留本地草稿，可重试 |
| 多次重复提交 | 提交按钮防抖 + 接口幂等性校验 |

> ⚠️ 上述异常处理在 Flutter 端尚未实现，且 z1-pwa 中也未找到完整换货流程代码（参考 Agent 调研报告：因 API 限额未深度调研换货异常分支）。本节为产品建议清单。
