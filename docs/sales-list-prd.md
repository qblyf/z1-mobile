## 一、功能定位

销售订单列表是零售开单完成后的**订单管理入口**，让职员和店长快速查找、筛选、查看订单状态，并支持退款等后续操作。

核心场景：
- 查找特定订单（订单号/会员姓名/手机号）
- 按时间筛选（今日/本周/本月/全部）
- 按状态筛选（全部/待付款/已付款/已完成/已退款）
- 查看订单详情
- 发起退款（需权限）

## 三、页面详细说明

### 3.1 销售订单列表 `/order/sales-list`

**顶部搜索栏**：
- placeholder："搜索订单号/会员姓名/手机号"
- 支持模糊搜索，实时过滤
- 搜索结果高亮匹配文字

**Tab 时间筛选**（横向滚动）：
- 今日 / 本周 / 本月 / 全部

**Tab 状态筛选**（横向滚动）：
- 全部 / 待付款 / 已付款 / 已完成 / 已退款

**订单卡片**：

| 字段 | 内容 |
|------|------|
| 订单号 | monospace 字体，带 `#` 前缀 |
| 时间 | 今日内显示 `HH:mm`，跨天显示 `MM-DD HH:mm` |
| 销售类型 | 零售/批发/工程（小标签） |
| 会员姓名 | 头像首字母 + 姓名 |
| 会员等级 | 颜色标签（普通/银卡/金卡/钻卡） |
| 商品件数 | "X件商品" |
| 实付金额 | 红色大字，已退款显示删除线 |
| 状态标签 | 颜色+文案 |

**订单卡片交互**：
- 点击 → 跳转订单详情
- 右滑 → 显示快捷操作（退款/取消，需权限）

**状态标签定义**：

| 状态 | 颜色 | 文案 |
|------|------|------|
| unpaid | 红色 | 待付款 |
| paid | 绿色 | 已付款 |
| finished | 蓝色 | 已完成 |
| refunded | 灰色 | 已退款 |

**下拉刷新 + 上拉加载更多**

**权限差异**：
- 职员：可查看列表和详情，不可操作退款
- 店长/管理员：可查看、可退款、可取消订单

## 四、API 接口需求

| 接口 | 方法 | 用途 |
|------|------|------|
| `/mall-order/list` | GET | 订单列表，按门店+时间+状态筛选 |
| `/mall-order/count` | GET | 各状态订单数量统计 |
| `/mall-order/detail` | GET | 订单详情 |
| `/mall-order/paid-cancel` | POST | 取消已付款订单（需审核+退款） |

**列表请求参数**：

```typescript
interface MallOrderListParams {
  departments: number[];        // 门店ID列表（从 token 自动获取当前门店）
  status?: MallOrderStatus;    // 筛选状态
  startDate?: number;           // 时间范围起点（时间戳）
  endDate?: number;             // 时间范围终点
  keyword?: string;              // 搜索关键词（订单号/会员名/手机号）
  page?: number;
  pageSize?: number;
}
```

## 五、状态机

```
unpaid（待付款）
   │ 超时/手动取消
   ▼
cancelled（已取消）
   │
paid（已付款）
   │ 退款审核
   ▼
refunded（已退款）
   │
finished（已完成）
```

## 六、与其他模块的联动

| 触发 | 联动 |
|------|------|
| 点击订单 | 跳转 `/order/:orderNumber` |
| 订单退款完成 | 刷新列表，该订单状态变为"已退款" |
| 退货审核通过 | 刷新列表，关联订单状态变为"已退款" |
| 新增零售订单 | 自动刷新列表（今日Tab） |
